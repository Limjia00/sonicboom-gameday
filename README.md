# SONICBOOM GAME DAY INTELLIGENCE
**수원 KT 소닉붐 홈경기 관중 수요 예측과 경기일 비즈니스 의사결정** — 공개 데이터만 사용한 개인 포트폴리오 (KBL·KT 구단과 무관, 로고·선수 이미지 미사용)

`index.html` 하나로 동작하는 정적 대시보드입니다(외부 파일 fetch 없음, GitHub Pages·`file://` 모두 동작).

- **범위**: 정규리그 홈 108경기(4시즌)
- **검증**: 시즌 단위 expanding-window, out-of-time 81경기
- **결과**: Model A MAE 518명 · Model B MAE 499명. 경기주간 정보의 추가 개선은 시즌별로 일관되지 않았습니다.

## 1. 프로젝트 질문
“다음 수원 KT 홈경기에는 몇 명이 올 가능성이 높고, 어떤 조건에서 관중 차이가 나타나는가? 그리고 그 정보를 경기일 운영 판단에 어떻게 참고할 수 있는가?”
시즌 일정 발표 시점(**Model A, 사전 계획**)과 경기 주간(**Model B, 경기주간 업데이트**)은 알 수 있는 정보가 다르므로 예측을 두 단계로 나눴습니다.

분석 단위는 **수원 KT 정규리그 홈경기 1개 = 1행 (2022-23 ~ 2025-26, 4시즌 × 27경기 = 108경기)**.
분석 범위는 2022-23~2025-26 정규리그로 고정했습니다. 2021-22 시즌은 수원 KT를 포함한 수도권 5개 구단이 무관중으로 개막한 뒤 수용 규모 20% 제한이 적용되는 등 관중 수용 조건이 달랐던 시기라 시즌 간 비교 가능성을 위해 제외했습니다([연합뉴스, 2021-10-15](https://www.yna.co.kr/view/AKR20211015138500007)). 플레이오프·챔피언결정전·컵대회도 포함하지 않았습니다.
**사용하지 않은/없는 데이터**: KT 내부 예매·MD·CRM 데이터(공개되지 않음), 경기별 이벤트·프로모션(일관 수집 불가), 풍속·적설·연장 여부, 타 구단 일부 홈 관중(가스공사 2022-25, 소노 2023-25: KBL 페이지에서 조회 불가).
상대팀 표시는 과거 경기에 현재 연고지/구단명을 소급하지 않도록 KCC, 고양 캐롯·소노, 안양 KGC·정관장처럼 시즌 간 비교에 안전한 명칭을 사용했습니다.

## 3. 분석 방법
- **경기 전 변수는 직접 계산**: 모든 팀 성적(승률·순위·최근 5경기·연승/연패·휴식일)은 해당 경기 **날짜 이전** 경기만으로 계산(시즌 최종 순위·승률 미사용). 자동 누수 점검 포함.
- **상대팀 흥행지수(ODI)**: 상대가 원정팀일 때 홈팀 시즌 평균 대비 관중 비율을 **이전 시즌만**으로 평균(표본 수축 k=3). 2022-23은 중립값 1.0.
- **캘린더**: 요일 유형(평일/토/일/평일 공휴일), 공휴일 전날, 시즌 시점. 낮 경기 변수는 데이터셋에 있지만 주말·공휴일 경기의 96%가 낮 경기라 **요일과 분리 불가**하여 모델 입력에서 제외(공선성 진단).
- **레벨 앵커**: 시즌 평균 관중이 1,548 → 2,472명으로 상승해, 다음 시즌 예측의 수준 기준으로 직전 시즌 평균 관중을 변수에 포함.
- **모델**: 후보 16개(Ridge / ElasticNet / RandomForest / HistGradientBoosting × 변수 4세트). 딥러닝 미사용. 선택 규칙: 폴드 2·3 통합 MAE 최저, 단 선형 모델이 5% 이내면 선형 선택. 채택: Model A = A / ridge, Model B = B+opp / enet. 전체 로그: `outputs/tables/model_selection_log.csv`.
- **예측구간**: 이전 폴드 out-of-time 잔차의 10·90분위수. **수요 등급**: 학습 시즌 관측 관중의 33·67분위수(LOW/MID/HIGH).

## 4. 검증 방법
랜덤 분할 미사용. **시즌 단위 확장 창 백테스트**: (학습 22-23 → 테스트 23-24) / (22-23~23-24 → 24-25) / (22-23~24-25 → 25-26). 폴드 1은 학습이 27경기뿐이라 보고만 하고 모델 선택에는 쓰지 않았습니다.

## 5. 결과 (81개 out-of-time 경기, 단위: 명)
| MODEL | MAE | RMSE | MAPE | R² | MAE 23-24 | 24-25 | 25-26 |
|---|---|---|---|---|---|---|---|
| Baseline 1 - training-period mean | 744 | 949 | 30.5% | -0.35 | 857 | 695 | 679 |
| Baseline 1b - previous-season mean (advance-plan naive) | 713 | 884 | 31.6% | -0.17 | 857 | 652 | 630 |
| Baseline 2 - last-5 home games mean | 759 | 894 | 38.3% | -0.20 | 842 | 754 | 682 |
| MODEL A - Advance Planning (A / ridge) | 518 | 679 | 21.2% | 0.31 | 643 | 501 | 410 |
| MODEL B - Game-week Update (B+opp / enet) | 499 | 664 | 21.6% | 0.34 | 649 | 393 | 455 |

- 최고 단순 기준(713) 대비 MAE 감소: Model A 27%, Model B 30%.
- **경기주간 정보 추가 효과**: 전체 MAE 3.7% 감소, 폴드 2·3 6.9%, 시즌별 -1% / +22% / -11% (양수=개선). → **일관된 개선이라고 주장하지 않습니다.**
- 80% 예측구간의 폴드 정직 커버리지: A 85%, B 85% (n=54). 수요 등급 정확 일치율 A 64%, B 68%.
- 주말 평균 2,681명 vs 평일 1,627명 (차이 +1,054, 95% CI 797~1,297); 4시즌 모두 같은 방향.
- **모델은 세 시즌 모두 과소예측**했습니다(실제−예측 평균, 명):
test_season    S43    S45    S47
model                           
A            598.0  436.0  330.0
B            482.0  203.0  347.0
- 상관≠인과, feature importance≠causal effect.

## 6. 실행 방법
```bash
pip install -r requirements.txt
python -m playwright install chromium   # verify_outputs.py의 브라우저 검증용 1회 설치
bash run_all.sh      # raw(data/raw) → 처리 → 검증 → 분석 → 모델 → index.html → 수치 자동검증
open index.html       # 또는 GitHub Pages
```
원자료(`data/raw`)는 공개 페이지(브라우저)에서 읽어 저장한 스냅샷입니다(절차: `src/browser_extraction_notes.md`). KBL/기상청 페이지는 JS 앱이라 스크립트만으로 재수집되지 않을 수 있어, 저장된 raw에서 시작해 이후 전 과정을 재현합니다. `src/verify_outputs.py`가 HTML의 주요 수치·브라우저 내 Planner 계산이 파이썬(scikit-learn) 결과와 일치하는지 자동 검증합니다.

폴더: `data/raw` · `data/processed` · `src/{collect_kbl,collect_weather,build_dataset,validate_data,analysis,train_model}.py` · `outputs/{figures,tables,model_metrics.json}` · `index.html`

## 8. 한계
예매 속도·좌석등급·시즌권/초청권 구분·CRM·MD 판매·프로모션 노출 데이터 없음 · 매진 근접 경기는 잠재 수요 확인 불가(Attendance ≠ True Demand; 좌석수 이력 미검증이라 점유율 분석 제외) · 한 구단 4시즌 108경기로 표본 작음 · 상관·예측 분석이며 인과 분석 아님 · 백테스트 3개 시즌 모두 과소예측 · 날씨는 일 단위 관측(예보 아님, 풍속·적설 미수집).
변수 구성과 모델 선택 과정에 본 데이터의 탐색 결과가 활용되었고, 후보 모델 선택과 성능 요약에도 같은 expanding-window 백테스트를 사용했습니다. 따라서 별도의 untouched 최종 holdout 성능은 아니며, 표시된 성능에는 개발 과정의 선택 영향이 일부 포함될 수 있습니다. 데이터가 더 쌓이면 이후 시즌을 최종 검증용으로 남기는 것이 필요합니다.
KT 내부 데이터가 있다면: 예매 D-30/14/7/1 curve, 좌석등급별 수요, 시즌권/일반권 분리, 신규/재방문 팬, CRM 세그먼트, MD SKU별 판매, 프로모션 exposure, 구매전환, 팬 LTV.
